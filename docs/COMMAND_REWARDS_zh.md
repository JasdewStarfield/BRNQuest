# 命令奖励

`brnquest:command` 从服务器执行任务书作者配置的一条命令。可以调用原生 `function` 完成多步效果，不需要 FTB Quests 运行依赖。

## 创建与字段

在奖励类型选择器选择“命令”，填写命令和需要的属性。可输入前导 `/`，草稿新增/更新时会规范化；运行时亦接受该写法。命令源实体为领取玩家，位置、维度取领取时的服务器状态，`@s` 指领取者，不授予玩家永久 OP。

| 字段 | 用途 |
| --- | --- |
| `title` | 可选显示标题，不填写时显示“命令” |
| `command` | 必填，单行命令，最多 32767 字符 |
| `source_mode` | `explicit`（指定等级）或 `player`（玩家权限）；新建默认 explicit |
| `permission_level` | explicit 模式的 0–4 级权限，新建默认 2；player 模式忽略此数值 |
| `silent` | 抑制原生命令输出，默认 false |
| `feedback` | 可选作者原文领取提示，与原生命令输出独立 |

例如 `give @s minecraft:paper 1`，或 `function eow:rewards/intro`。支持 `{p}`（玩家名）、`{x}` / `{y}` / `{z}`（领取时方块坐标）占位符；JSON/SNBT 花括号保持原意。FTB 团队、章节、任务占位符尚未映射，会拒绝无声执行。

服务端 `serverconfig/brnquest-server.toml` 的 `commandRewardPermissionLimit` 限制命令源最大等级，默认 2。explicit 超过上限会在领取预检拒绝；player 模式使用当前玩家权限与服务器上限两者中的较低值。作者无法通过客户端领取参数提供命令或改变这个上限。

语法不完整、权限不足、超出服务器上限和无效配置会在执行前拒绝，不开始一次领取尝试。涉及具体目标存在与否等运行期条件，仍可能在执行中失败；预检不是执行一遍命令。

## 领取与异常处理

个人奖励按玩家领取；团队共享一次性奖励只由首位合资格领取者触发，命令中的 `@s` 指该领取者，不会自动遍历队员。

命令尝试在世界目录 `data/brnquest-command-rewards/` 写入独立记录。执行意图文件使用排他创建并强制刷新文件，随后才调用原生命令；结果另行记录。命令不会因重复包、重新打开界面、任务书 revision 改变或普通领取存档落后而自动重放。

命令成功或管理员确认后才记为已领取；失败/未知尝试阻止重试，并保留奖励等待处理。原生命令回调报告的结果是诊断证据，不证明外部模组所有副作用都已完整完成。由另一条命令/函数发起领取时，执行可能进入原生命令队列，结果到达后会继续更新领取状态。

管理员查询当前周期记录（权限 2）：

```mcfunction
/brnquest command_reward status <玩家> "namespace:reward_id"
```

记录包含状态、attempt UUID、原生回调数量、结果数值及说明；完整展开命令保存在受服务器管理的意图文件中。`UNKNOWN` 表示没有可靠结果，既可能尚未执行，也可能已经执行。

核实实际效果并自行处理必要补偿后，管理员可以确认消耗本次奖励（权限 4）：

```mcfunction
/brnquest command_reward acknowledge <玩家> "namespace:reward_id" <attempt UUID>
```

此命令**不会重放命令**；它确认奖励已处理，再经当前资格/owner 校验更新领取状态。UUID 防止确认错误记录。没有自动 retry 或“回滚后再发”入口。

重复任务的新周期使用独立记录。普通任务重置不会删除历史命令记录；回到相同周期号时旧记录仍防重放，需要额外效果时由管理员核实后显式执行补偿。备份/恢复世界时应一并保留这些记录，不把仅恢复普通进度文件当成完整回滚。

文件强制刷新不能让任意命令副作用与世界保存成为原子事务；崩溃、底层存储故障、回档或外部模组异常仍可能留下结果未知。损坏记录会拒绝读取，不当成“从未执行”。该机制优先避免不确定命令自动重放，不承诺跨崩溃严格一次执行或无损回滚。

## FTB 导入

支持 `command` / `ftbquests:command` 奖励，规范化命令字符串与 silent。FTB 缺省 permission_level=0 转 player；旧 elevate_perms=true 优先转 explicit/2。源字段保留用于追溯。

FTB `feedback_message` 是资源翻译键。无法从任务书输入解析该资源键时，保留为 `ftb.feedback_message` 并输出 BQF-107，作者应填写原生 `feedback` 文本后再发布；不依赖已卸载 FTB 的语言资源。非空反馈覆盖这项待修复检查，源键仍保留。团队等不支持的占位符必须由作者调整。

数据 schema、网络协议与原有 RewardType API 均保持不变；命令类型的实际执行由服务端领取协调器负责，直接调用通用 RewardType.execute 不能绕过尝试记录。
