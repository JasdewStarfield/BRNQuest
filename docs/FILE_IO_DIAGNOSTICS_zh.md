# 文件读写故障日志

奖励记录、命令回执、草稿、世界内编辑、工作区发布/部署和备份的关键文件操作，失败时会向正常 Minecraft 日志写入 `[BRNQuest/FILE_IO]`。无需开关；正常成功读写不逐条输出。

记录包含操作类型与选项（读取、写入/强制落盘、目录创建、复制、原子移动、临时文件创建和清理）、进程及事件编号、线程、耗时、规范化绝对路径、源/目标及父目录的状态、异常类型、系统返回的 reason 和完整调用栈。路径状态是在异常发生后、调用方清理前尽力采集，不是权限或锁状态的原子快照；文件内容不会写入诊断字段。诊断失败不替换原始读写异常。

奖励表已有的有限重试规则保持不变。一次移动失败即留证，后来重试成功会另记 `recovered operation=reward-table-replace` 和重试次数，可按源临时文件及目标路径关联。

再次遇到问题时，保留对应实例的 `logs/latest.log`（日志已轮转时保留对应 `.log.gz`），记下时间与当时操作。单人游戏查客户端实例日志，专服查服务端日志；开发客户端默认是 `run/logs/latest.log`。搜索 `[BRNQuest/FILE_IO]` 并保留其后的完整堆栈，不能只摘最后一行 `TABLE_BLOCKED` 或 `DRAFT_WRITE_FAILED`。

Java 异常与路径状态不提供占用文件的外部进程名称。若确认是系统访问拒绝但日志不足以区分占用或权限，需要后续结合操作系统文件访问跟踪核对；不能仅凭 AccessDeniedException 判定杀毒软件或某个进程。此功能仅补充证据，不改变原子替换、回滚、清理、重试和发奖策略。

失败日志还会列出 `overlapping`：采样时仍在执行、且源/目标路径与失败操作相同或存在父子关系的内部操作（最多列出 16 条，`observed` 为采样匹配数），含事件、线程、路径和耗时。它只覆盖接入追踪的操作，不是历史列表或操作系统句柄列表；`observed=0` 不能排除更早结束的并发操作或外部占用。事件编号包含成功操作，因此出现跳号是正常的。
