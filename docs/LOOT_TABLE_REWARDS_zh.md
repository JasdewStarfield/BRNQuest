# 原生战利品表奖励

在奖励类型选择器中选择“原生战利品表”（`brnquest:loot_table`），填写一个 `loot_table` ID，例如 `minecraft:chests/simple_dungeon`，或通过服务端列表选择当前已加载的表。`title` 是可选显示标题。原生数据包路径为 `data/<namespace>/loot_table/<path>.json`；这与 FTB 的外部奖励表不同，FTB 的 random/loot 继续导入为 `brnquest:reward_table`。

每次领取只生成一次，使用领取玩家所在维度、位置、玩家实体和幸运值。不会伪造被击杀实体、伤害来源、工具或方块状态；表及其引用要求缺失上下文时拒绝领取。原版箱子表、使用这些参数的数据包表及合法空表可使用，不保证所有 loot context 类型均兼容。生成沿用 NeoForge 原生路径，包括全局战利品修改器。

战利品表不提供单独的详情按钮；未自定义标题时条目摘要显示表 ID，规则说明保留在编辑器字段提示中，不提供试抽。生成后的物品及组件先保存到领取记录，再按物品奖励相同的入包/溢出掉落规则交付。空结果正常记为已领取。每次生成最多保存 1024 个非空物品栈、4096 个物品及 512 KiB 序列化数据；整个组合尝试仍受 2 MiB 回执预算约束，超限不会交付。

可以作为 all/random/choice 奖励表的叶子；重复抽中分别生成独立结果，自选未确认分支不生成。所有必需选择完成前不交付。编辑任务书、关闭窗口、重新登录不会改变已经保存的结果。数据包重载只决定新尝试；若资源指纹变化，未完成尝试会阻断并保留原结果，不重新抽取或自动替换。

交付中断且缺少持久成功证据时进入待审核状态，不自动重发，以避免重复物品。沿用管理员 `/brnquest reward_table status <player> <reward>` 查询，以及权限等级 4 的 `acknowledge` / `retry` 恢复入口；仅明确没有副作用的失败允许重试。管理员确认表示接受既有副作用并继续，不会补发不确定的物品。详见 [奖励表恢复](REWARD_TABLES_zh.md)和[故障日志](FILE_IO_DIAGNOSTICS_zh.md)。
