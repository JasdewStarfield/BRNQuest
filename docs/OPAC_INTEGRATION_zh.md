# Open Parties and Claims 联动

BRNQuest 在 Minecraft 1.21.1 NeoForge 上支持可选的 Open Parties and Claims（OPAC）**0.30.3**。安装这一版本后自动使用其 party UUID 作为共享进度身份。BRNQuest 只读取身份和成员；建队、邀请、退出、领地和常加载仍由 OPAC 管理。

## 进度归属

| 状态或操作 | BRNQuest 行为 |
| --- | --- |
| 未安装 OPAC、版本不支持、未组队或 API 暂不可用 | 使用 `brnquest:personal/<玩家 UUID>` |
| 加入受支持的 OPAC party | 使用 `brnquest:openpac/<party UUID>` |
| 新建队伍 | 新账本从空进度开始，不复制队长的个人进度 |
| 入队、换队 | 切换到账本已有进度，不复制或合并其他账本 |
| 退出、被踢 | 恢复自己的个人历史；原队伍数据保留 |
| 转让队长 | party UUID 不变，账本不变 |
| 解散、删除、过期 | 保留旧账本并归档；同一 UUID 再出现时可恢复 |
| 卸载 OPAC、查询异常 | 保留共享账本，回退个人；不把异常当成解散 |

当前不提供自动或手动跨 owner 复制。队伍之间即使显示名或队长相同，也不共享账本。第三方 provider 注册不会自动取代这项选择策略。

## 奖励、离线成员和重复任务

- 任务目标进度、完成状态、完成轮次和冷却由队伍共享。物品提交仍只扣除实际提交者的物品。
- 每轮完成时冻结完整成员 UUID 名单，包含队长和离线成员。
- 普通奖励（`team_reward=false`）由名单内每个成员各领一次；退出后不能代领队伍奖励，重新加入同一队伍仍保留原领取记录。
- 显式团队奖励（`team_reward=true`）整队每轮只发放一次，给第一个有资格的实际领取者。不会向全体成员广播物品、经验或命令奖励。
- 后来入队者可查看已经完成的进度，但没有旧轮次奖励资格，领取返回 `NOT_ELIGIBLE`。下一轮完成时重新确定成员名单。
- 自动奖励通过相同账本发放；在线成员在服务端定期检查时补领，离线成员重新上线且仍在同一队伍时补领。没有离线执行玩家命令或模拟客户端。
- 默认重复任务需要完成时名单中的所有成员领完普通奖励，并领完团队奖励，才在冷却结束后开启下一轮。成员离线或退队不会悄悄取消这项阻塞；可由作者显式设置 `ignore_reward_blocking`，或管理员重置任务。忽略阻塞开启新轮次后，上一轮未领资格不再保留。
- HUD 追踪独立于共享完成状态。切换自己的追踪不会修改队友的焦点。个人账本的原有追踪与共享模式下的个人焦点分别保留。

`ProgressView` 和客户端快照按当前查看者投影已领奖标记及追踪状态，不能把一个成员的投影当作全队的领取清单。管理员重置队伍任务影响整个共享账本及其成员领取记录。

## 更新时机与降级

所有身份查询发生在服务器主线程。登录、进度写入前均重新查询公开 API；每 100 server tick 对在线玩家及已保存的 OPAC owner 对账。成员变化后，在线队友获得各自的权威进度快照。

精确版本条件 Mixin 仅缩短刷新等待：它发送失效通知，下一服务器 tick 再查询公开 API，不直接搬运进度。启动日志的 `BRNQuest/OPAC` 会报告注入健康状况；注入不可用时登录、写入前查询和 100 tick 轮询继续工作。其他 OPAC 版本保留加载能力，但关闭共享 provider 并给出日志，不视为已支持组合。

## 存档与扩展作者

进度存档升级为 schema 2，以 provider ID 和 UUID 双层存储。原 schema 1 的 `players` 数据只迁移到个人命名空间，不复制进队伍。未知 provider、归档账本、orphan 任务、离线领奖记录均继续保存。任务书定义仍使用原有 schema，与进度存档版本不同。

升级会在后续保存时写入新进度格式；回退旧版本前需恢复升级前的世界备份。旧版本不识别 schema 2 的 owner 账本。

扩展奖励如果使用全局去重存储，应把普通团队奖励的领取者 UUID 纳入去重键；同队不同玩家不是重复投递。KubeJS 的 `idempotencyKey` 已按此区分，个人奖励与团队一次奖励保留原有键结构。OPAC 公开 API 的授权依据是 UUID，而不是用户名、显示名或队长身份。
