# 奖励表

`brnquest:reward_table` 提供可嵌套的 `all`（全部领取）、`random`（随机抽取）和 `choice`（自选一项）：支持物品、经验、经验等级、命令、进度、内置 custom，以及明确声明组合能力的 Java 扩展。未适配的脚本奖励仍不可组合。

在奖励编辑器添加“奖励表”，可在外层属性填写“显示标题”；留空使用默认名称。打开“编辑配置”，点击“添加条目”，从类型列表选择子类型并填写属性。条目列表和属性页使用滚轮滚动；点击条目编辑，右击或点击“更多操作”可更换类型、排序、复制或删除。复制生成新 ID，排序保留 ID；更换类型从新类型的默认配置开始，取消不会替换原条目。子表单确认只修改父表本地草稿，父表取消放弃修改；确认父表后仍须提交外层奖励属性和任务书草稿。普通编辑保留未知字段，不支持的树版本只读保留。

只读预览和状态查询不会创建领取尝试。点击领取先预检全部叶子，再执行；每 tick 最多 8 个同步叶子，命令 PENDING 暂停后续项。共享根绑定首次领取的执行者，其他成员不能替换执行者；重新登录后再次点击可恢复已有尝试。根资格、团队规则、重复周期及正常账本仍由服务器控制。

在条目窗口顶部选择“随机抽取”，再打开“抽取设置”：抽取次数为 1–64 次，可设置允许重复抽中（有放回）及空结果权重。条目的“更多操作 → 权重与必给”配置正权重或必给。必给项按列表顺序只发一次，且不进入随机池；其后按抽取顺序发放。同一条目重复抽中会分别发放。无放回只移除抽中的普通条目，空结果仍可重复抽中；普通池耗尽且空权重为零时提前结束。切换回全部领取会保留随机参数，但不使用它们。

抽取前预检全部候选；抽取结果及空结果在任何发奖前保存。重登、重新点击、作者改表都不改变已有尝试的结果。只含必给项或正空权重的表合法；全部抽空仍消耗本轮领取，并显示“本次未抽中物品或奖励，领取已完成”。预览只显示规则，不进行试抽。

在条目窗口顶部选择“自选一项”，并将根奖励领取策略设为“手动”。玩家点击领取后，会打开服务端冻结候选的选择窗口；单击一项，再点击“确认领取所选项”，只发放这一项。物品与数量在列表显示，更多候选通过“加载更多选项”继续加载，所有选项都可访问。关闭或断线不会默认选择第一项，也不会发奖；重新领取会恢复同一尝试。作者改表不会替换等待中的候选。确认一旦保存就不能改选，重复提交相同确认不会重复发奖。

自选模式不使用随机权重、必给或抽取次数，但保留这些配置。自动领取策略与需要选择的奖励冲突，发布校验会报错；一键领取会跳过并提示单独领取。FTB choice 映射到原生自选，不要求随机模式的 loot_size 或正总权重；子表仍拒绝。

权重使用精确十进制比例的整数抽签，不舍入为整数权重；最多 34 位有效数字，去除尾零后的小数 scale 为 -308..324，且数值及权重总和须在有限 double 范围内。条目权重须大于零，空权重允许为零。配置上限为 64 KiB UTF-8、256 个总节点（含根），物品叶子最多交付 4096 个物品。超限拒绝，不截断。全部领取与自选模式拒绝空表；随机模式无条目时必须有正空权重。尝试记录最多 2 MiB；1024 个未完成尝试或日志目录达到 256 MiB 后拒绝新建，保留旧证据。

强制落盘日志位于世界的 `data/brnquest-reward-tables`。命令同时使用独立命令日志。崩溃仍可能发生在效果与结果记录之间，因此不承诺通用 exactly-once；不确定叶子停止且不自动重放。请勿删除日志来解决领取问题。

权限等级 2 查询当前周期的根、执行者、attempt、逐叶 occurrence、状态与时间：

```text
/brnquest reward_table status <玩家> "<根奖励ID>"
```

等级 4 的管理员核对实际效果后，可确认指定不确定叶子；确认不补发该叶子，只继续未开始的剩余项：

```text
/brnquest reward_table acknowledge <玩家> "<根奖励ID>" <attempt> "<occurrence>"
```

仅明确 `FAILED_NO_EFFECT` 可受控重试，须重新通过预检、资源和适配器版本校验：

```text
/brnquest reward_table retry <玩家> "<根奖励ID>" <attempt> "<occurrence>"
```

资源变化、损坏文件及失效周期不会被重新点击绕过；保留记录并核对。当前命令按玩家当前周期查询，旧周期证据仍在日志目录。数据包函数等相关资源摘要改变会阻断旧执行清单，任务书编辑不会自动重抽或重新解释原条目。

FTB v13 `all_table`、`random`、`loot` 和 `choice` 从外部 `reward_tables` 或内嵌 `table_data` 展开为独立快照。random 不使用源空权重，loot 保留空权重；二者将合法 loot_size 映射为有放回抽取次数，零权重条目转必给。缺失或非法 loot_size、非正/溢出的总权重、缺失引用、循环引用和不可提升的子领取策略报错，源字段仍保留。FTB loot 不等于原生 Minecraft 战利品表，后者尚未开放。

网络协议为 18，客户端和服务端需同步更新。扩展接口见 [EXTENSION_API_zh.md](EXTENSION_API_zh.md)。

领取遇到读写故障时，日志记录格式与保留方式见 [文件读写故障日志](FILE_IO_DIAGNOSTICS_zh.md)。

## 嵌套与恢复

条目类型选择器现在包含奖励表。子表可以设置独立标题，并通过其“编辑条目”进入下一层；顶部显示层级路径，返回会保留父草稿，确认根表前不会提交服务端。全部领取、随机和自选可以混合。根表任何分支包含自选时，整根仅允许手动领取。

每个随机抽中的子表独立展开，重复抽中也会产生不同的 occurrence。服务端依次显示当前待确认的选择路径，所有必要选择完成后才开始发奖；关闭窗口或重登不会默认选择、重新抽取或提前领取其他包。新尝试使用 journal version 2，旧 version 1 单层尝试保持原恢复方式；无需迁移或删除记录。

深度最多 8 层（根为第 1 层），配置总节点最多 256，最坏展开叶子最多 1024；展开表与叶子节点另受 16384 上限和 2 MiB 回执预算限制。超限直接拒绝，不截断。FTB 重复引用会复制成独立子树，真正循环引用与超限会报错。管理员 status 显示待确认选择路径及各叶子 occurrence；acknowledge/retry 仍只处理指定叶子，不从头重放奖励包。
