# BRNQuest 阶段 5 验收记录

## 第一批：编辑入口、目录、会话与只读草稿预览

> 对应计划项：5.1 与 5.2 的基础链路。第一批不提供节点或属性修改；它先冻结目标服务器权限、任务书选择、编辑租约、草稿同步和不重排现有界面的交互边界。

### 已实现行为

- `AuthorApi.catalog` 只向目标服务器权限等级 2 的在线管理员返回可成功解码的服务器草稿；目录按完整 `namespace:path` 稳定排序，客户端本地文件不参与。
- 网络协议当前为 `3`：在协议 2 的目录、会话和草稿分块上增加冲突恢复请求与位置差量响应。服务端限制目录数量、元数据大小、任务书大小、节点数量和单块大小；客户端和服务器必须使用匹配构建。
- 客户端使用独立 `ClientEditorState` 接收并校验草稿；active 玩家任务书不被草稿覆盖。草稿 ID、内容 revision、字节数或分块身份不一致时不会进入编辑模式。
- 编辑会话每 30 秒自动续租。关闭界面、正常退出编辑模式、切换任务书和断线均沿用服务端租约释放语义；若玩家在打开请求尚未返回时关闭界面，迟到的租约会立即关闭。
- `QuestScreen` 保持既有左侧导航 `150px`、右侧详情 `250px`、折叠把手和画布边界。标题/ID、目录、编辑开关与会话状态均绘制为原画布范围内的悬浮层，查看/编辑切换不会改变三块主区域的像素宽高。
- 浏览相机、章节、缩放和导航折叠状态按“服务器 + 任务书 ID”隔离；切换两本任务书不会复用另一书的视口状态。
- 编辑草稿中的节点使用中性编辑配色，任务与奖励行不接受游玩提交/领取输入，避免把作者预览误当作 active 进度界面。

- 默认 `runGameTestServer`：16/16 required GameTest；远程管理员用例增加“普通玩家目录拒绝、管理员读取目标服务器目录”检查。

4. 记录左栏、画布和右栏边界，进入编辑模式后再次截图；三块区域边界必须保持原坐标，仅新增画布内悬浮元素。

若发现问题，请保留进入前后截图、GUI scale、窗口尺寸、任务书 ID、左下角稳定错误代码和服务端 `latest.log`。

## 第二批：当前任务书入口、可辨识目录与任务属性修改

- 右下角入口改为“编辑当前任务书”。当前生效任务书尚无草稿时，目标服务器在重新检查管理员权限后创建 `ACTIVE` 来源草稿；已有草稿则复用，并统一通过租约与 revision 检查打开。
- 标题下拉菜单在没有搜索词时只展示与当前画面任务书 ID 完全相同的草稿，避免历史测试、导入和备份草稿淹没常用目标。输入标题或完整/部分 ID 后才搜索其他服务器草稿。
- 目录行在不改变导航栏、画布和详情栏宽度的前提下扩展为“标题 + ID”两行；悬停提供不截断的标题、完整 ID 和来源说明。
- 编辑模式中选中任务节点后，右侧详情固定显示“编辑任务属性”。首个可写表单覆盖标题、副标题和描述；任务 ID、章节、坐标、依赖、任务条件、奖励和未知扩展内容保持原值。
- 客户端只发送字段级意图。服务器重新读取会话快照、按稳定任务 ID 构造候选、运行 `DraftBookEditor` 与增量验证，再返回新 revision 的完整草稿分块；客户端验证完成前继续显示上一个可信草稿。
- 属性表单在打开时不再渲染其下方的 task/reward 物品图标；任务书下拉层使用高于普通物品的 GUI 深度、低于最终 tooltip 的深度。文本框为失焦文字显式指定可读颜色。
- 增量提交只阻止本次修改新增或增加数量的 `ERROR/FATAL` 诊断。草稿原本已有的未知扩展诊断不会阻止标题等无关字段修改，未知配置仍逐字保留；真正新增的非法空标题等问题仍会被拒绝。
- 任务属性表单的“完成”只提交到服务器内存编辑会话；底部明确显示“保存草稿”，成功后状态变为“草稿已保存”。保存相对磁盘基线比较诊断，因此已有未知扩展不会阻止持久化，新错误仍会被拒绝。
- 草稿未保存时，退出编辑、切换任务书或按 Esc 都先显示丢弃确认。若界面被其他界面强制替换，客户端保留仍有效的会话投影，重新打开任务书可在租期内继续编辑；断线仍由服务器释放会话。
- 顶部任务书标题/选择栏与底部状态/保存/退出栏占用固定的全屏宽度。导航、画布和详情面板统一限制在两条快捷栏之间；反复展开左右面板不会改变快捷栏控件的位置或宽度。

## 5.3–5.4 章节结构与任务节点编辑

1. 在编辑模式左栏使用“+ 组”创建章节组，再使用“+ 章节”或章节组右键菜单创建章节；完整 ID 必须使用 `namespace:path`，显示名称可随后通过右键“改名”修改。
2. 对章节组和章节分别执行“向上移动/向下移动”，确认顺序在服务端草稿同步完成后稳定，并在保存、退出、重新进入后保持。
3. 删除非空章节或章节组，确认界面先显示受影响章节数、任务数和依赖清理范围；取消不应改变 revision，确认后不得留下悬空任务或依赖。
4. 在章节空白画布右键创建任务节点；节点右键可以复制或删除。复制必须产生新的 quest/task/reward 稳定 ID，不能与原节点共享子对象 ID。
5. 左键拖动单个节点；按住 Ctrl 选择多个节点后拖动任一已选节点。拖动期间只本地预览，松开后一次提交全部最终坐标；缩放、平移和左右栏切换不改变已保存图坐标。
6. 保存草稿并退出编辑，再重新进入，确认章节结构、节点数量、顺序和坐标全部恢复。客户端视觉验收同时覆盖 720p/1080p、GUI scale 2/3、菜单边缘自动收拢和危险确认层级。

## 后续编辑功能的 UI 组件基础

- `client/ui/component` 统一提供 `UiRect`、`QuestScreenLayout`、编辑按钮、编辑文本框、滚动条、弹出菜单、确认对话框和单一活动弹层宿主。后续依赖、task、reward 和发布界面应复用这些组件，不再在 `QuestScreen` 中复制颜色、矩形和命中算法。
- `QuestScreen` 仍是页面编排与语义操作边界：组件只负责布局、绘制、焦点或命中结果，不持有编辑租约、revision，也不直接发送网络 mutation。
- 画布节点和依赖连线继续使用即时渲染、视口裁剪及图坐标命中；不会为每个节点创建原生 Widget，以免节点数量增加后引入不必要的对象和变换复杂度。
- 任一时刻最多存在一个捕获输入的编辑弹层。目录、右键菜单、结构表单、删除确认和丢弃确认共享 Esc、滚轮、拖动及外部点击屏蔽规则，防止输入穿透到底层画布。
- 自动测试固定上下快捷栏、左右面板对中央画布的影响、内容区边界、底栏状态宽度、弹出菜单边缘收拢、确认框按钮位置及弹层互斥。加入依赖候选、循环判断、双行选择器、稳定 ID 重命名、进度迁移、双模式图标、发布状态机和紧凑表单几何测试后，完整 JUnit 当前为 135/135。

## 5.5 依赖关系编辑

- 编辑模式的任务详情底部拆分为“基础属性”和“依赖”两个入口；依赖页始终用“前置任务 → 当前任务”说明数据方向，避免把 prerequisite 与 dependent 反向理解。
- 已有依赖按稳定完整 ID 列出并可逐条移除。缺失引用仍可见且可清理，不会因为解析失败从界面静默消失。
- “添加依赖”打开全任务书双行选择器，可按任务标题、章节标题或完整 `namespace:path` 搜索，因此能添加跨章节前置任务；现有依赖和当前任务不会重复出现在候选中。
- 客户端沿候选任务的依赖边检查是否可回到当前任务，并以警告图标、文字和颜色共同标识循环候选。该检查只改善即时体验；`ADD_DEPENDENCY` 和 `REMOVE_DEPENDENCY` 仍提交目标服务器，由权限、会话 token、预期 revision 和 `AuthorValidationService` 重新校验，非法循环不会进入新 revision。
- 添加或移除成功后继续通过完整可信草稿分块替换客户端预览；保存按钮仍是写入磁盘草稿的显式边界，active 任务书不会提前改变。

### 5.5 客户端人工检查

1. 选择一个没有依赖的任务，进入“依赖”，从同章节添加一个前置任务；确认列表显示“前置 → 当前”，画布箭头也从前置指向当前。
2. 搜索另一个章节的标题或任务完整 ID，添加跨章节依赖；保存、退出并重新进入编辑模式后，该依赖必须恢复。
3. 删除一条已有依赖，确认同步完成后列表和同章节画布连线同时消失；保存前底部显示“草稿未保存”。
4. 构造 `A → B` 后编辑 A 的依赖选择器，确认 B 明确显示“会形成循环”，点击不会提交 revision，也不会只依靠颜色表达警告。
5. 在较长任务书中输入、退格和滚动搜索结果；选择器打开时，滚轮、点击和拖动不得穿透到底层画布。
6. 在服务端 revision 已变化、会话过期或权限被撤销时尝试添加依赖，确认客户端显示稳定错误状态，并且服务端草稿保持上一合法版本。

## 5.6 任务基础属性编辑

- 任务属性表单在原详情栏宽度内使用统一的紧凑标签/输入行，覆盖稳定 ID、标题、副标题、说明和双模式图标；该行布局将继续供 task/reward 与描述驱动表单复用。
- 标题、副标题、说明和图标与稳定 ID 一起作为一个服务端权威事务提交。服务端重新核对会话、任务书、revision、容器、物品注册表和重复 ID，并在增量校验通过后才生成一个新 revision；客户端不会把同一属性表单拆成多个易冲突请求。
- 普通属性编辑不再暴露仅影响序列化的“章节内顺序”，并始终保留任务原有列表位置。节点图坐标、章节归属、依赖、task、reward 和未知扩展字段不会被普通属性更新覆盖。
- 稳定 ID 变化必须经过独立确认层。确认信息显示会被改写的依赖引用数量，并明确说明发布/reload 后的进度迁移边界：任务完成、可用和追踪状态从旧 ID 迁移到新 ID；task/reward 使用各自稳定 ID，进度与领取账本不重命名也不清空。
- 重命名事务会更新全书所有指向旧任务 ID 的依赖，并把旧完整 ID 记录为指向新 ID 的别名。在线玩家在 reload 后立即迁移，离线玩家在下次进入并执行权威 reconcile 时迁移；重复 reconcile 为无变化操作。
- 图标字段提供“物品 / 纹理”显式切换：物品模式接受已注册物品 ID，由服务端生成规范 SNBT；纹理模式接受任意合法 `namespace:path` Resource Location，并直接渲染客户端已加载资源包中的纹理。两种模式都在输入行右侧即时预览；未修改时完整保留旧物品 SNBT/组件，空字符串继续使用默认任务视觉。

## 5.7 task/reward 列表与既有条目编辑

- 任务详情底部现在提供“条件”和“奖励”页签；每行使用与游玩任务界面相同的 presentation registry 显示物品或符号图标、本地化类型名，并把对象稳定 ID 放在第二行。完整类型 `namespace:path` 保留在悬停提示中，未知类型仍显示原始类型 ID 与警告色。
- 可对 task/reward 执行添加、服务端无损复制、向上/向下排序和删除。每次动作仍以 task/reward 稳定 ID、所属 quest ID、编辑会话和预期 revision 为边界，客户端只在验证完整草稿分块后替换预览。
- 点击行或铅笔按钮可编辑已有条目。内置类型根据阶段 3 字段描述生成文本、数字、布尔、枚举和物品输入，并同时编辑 task optional 或 reward claim policy/team reward；未知类型显示“原配置已保留”的只读后备，不会用空表单覆盖扩展字段。
- task/reward 稳定 ID 可以显式重命名，提交前必须再次确认。服务端拒绝与任意现有 task/reward 冲突的 ID，并写入 `@task:`/`@reward:` 迁移别名；发布 reload 时分别迁移累计 task 进度与 reward 已领取账本。
- 复制由服务端从当前权威草稿读取源对象，因此未知类型的配置 map、task optional、reward claim policy 和 team reward 不经过客户端重建；排序也只改变列表位置。
- 类型选择器列出 BRNQuest 内置类型以及当前草稿中出现的完整类型 ID。空配置可通过 Codec 的类型可直接创建；`brnquest:item` task/reward 会进入独立物品选择屏幕，从玩家背包复制 count=1 的完整 ItemStack SNBT，并与创建动作作为同一个服务端 revision 提交。其余需要必填配置的类型仍等待 5.8 描述驱动表单。
- 未知或缺失类型以文字和警告色共同标记，原配置保持可复制/排序。`BQV-117`/`BQV-118` 与发布完整校验继续阻止未知类型被不安全发布，列表编辑不能绕过这一边界。

### 5.7 客户端人工检查

1. 在同一任务中分别打开“条件”和“奖励”，添加 `brnquest:checkmark`、`brnquest:custom` task 及 `brnquest:custom` reward；确认每行第一行显示对应图标和中文类型名、第二行显示稳定 ID，悬停可见完整类型 ID，底部进入未保存状态。
2. 对每种对象执行复制、连续上移/下移和删除；确认每次只产生一个新 revision，保存、退出并重新进入后列表顺序稳定。
3. 使用含未知 task/reward 的测试任务书，确认未知行仍显示完整 ID 与类型警告；复制与排序后其 config、optional、claim policy 和 team reward 原样保留，发布仍被对应诊断阻止。
4. 打开列出 `checkmark`、`custom`、`item` 的类型选择弹层，分别用 Esc、标题栏“×”和点击弹层外退出；三种方式都必须立即回到 task/reward 列表且不提交 mutation。随后选择 task/reward 的 `brnquest:item`，确认进入独立物品选择屏幕；点击背包物品或将其拖到目标槽后，原背包数量和组件完全不变，目标槽只显示 count=1 的幽灵副本。右键目标槽可清除，空目标不能完成。
5. 点击“完成”后确认返回同一个 task/reward 面板且编辑会话未关闭；新增对象与 `item`/`count` 配置只产生一个服务端 revision。取消或按 Esc 必须立即返回且不得提交 mutation；背景模糊只能位于选择器面板、槽位、物品和文字之下。
6. 使用带附魔、耐久或自定义组件的物品完成选择，保存并重新进入后确认预览/运行时匹配所需组件；本轮无需安装 JEI，也不验收 JEI 列表拖入。

## 5.8 JEI 可选联动与字段级诊断

- JEI 只作为客户端 optional 依赖：编译使用 `common-api`/`neoforge-api`，开发运行使用不进入发布 POM 的 `localRuntime`。当前固定 JEI `19.25.1.334`，其模组元数据要求 NeoForge `21.0.118-beta` 以上，覆盖项目的 `21.1.216` 基线；`-PexcludeJei` 用于验证完全无 JEI 的构建和运行路径。
- 所有 JEI 类型只存在于 `compat.jei` 包。BRNQuest 核心、服务端与普通客户端类不引用该包；JEI 安装时通过 `@JeiPlugin` 自行发现集成入口，未安装时 JVM 不解析这些外部接口。
- 物品选择器是带明确父 `QuestScreen` 的普通子 Screen，因此 JEI 在首次打开时就收到完整 Opening/Init 生命周期。Screen handler 使用选择器自身的最终 panel 几何布置物品列表；ghost handler 仅为 ItemStack 返回目标，目标矩形与选择器渲染/命中测试共用同一布局；接受时复制完整组件并强制 count=1，不移动或消耗来源。
- 选择器每帧先绘制并 tick 被挂起的父编辑器，再对完整父画面执行模糊/暗化，随后绘制遮罩和槽位；JEI 的屏幕后置渲染保持在最终前景。JEI 配方页通过 `setScreen` 往返后，选择器背景仍是同一个任务界面；完成、取消或 Esc 会恢复同一编辑器对象、字段输入、未保存草稿和服务端租约。
- 描述驱动表单把 `ConfigFieldIssue.fieldKey` 映射回对应行，以 `!`、错误色和顶部具体文本共同提示。ItemStack 字段在客户端先用当前注册表解析 SNBT；服务端仍保留最终权威校验。
- task/reward 更新表单在服务端处理及可信草稿分块同步期间保持打开并禁用输入。成功且完整草稿验证后才关闭；拒绝时恢复可编辑状态，保留全部输入，并根据结构化 `objectId/path` 聚焦 ID、领取策略或具体 `config.<field>`。
- 2026-08-22 自动与启动门禁已通过：`build -PexcludeJei` 为 151/151 JUnit；默认客户端在 NeoForge `21.1.216` 上加载 JEI `19.25.1.334` 并完成 GUI handler/runtime 注册；`-PexcludeJei` 客户端完成 BRNQuest 初始化与资源加载，专服启动到 `Done`。两条无 JEI 日志均未出现 `mezz.jei` 缺类错误。下列可见布局、拖入和焦点行为仍由客户端人工验收决定。

## 5.9 原始配置后备视图

- 已注册但没有字段描述、或字段描述提供器抛出异常的 task/reward 类型，在既有属性表单中显示“原始配置”入口。独立子 Screen 使用可滚动多行输入框编辑确定性格式化的 JSON，并持续 tick 同一个父编辑器，取消或 Esc 不改变表单输入和服务端租约。
- 原始文本只接受 schema 1 的扁平 JSON 对象；字符串、数字和布尔 primitive 统一转换为字符串 map，嵌套对象、数组、空键、超过 64 项及越过协议字段长度的内容在本地直接拒绝。重新打开时所有值都按 JSON 字符串输出，避免类型猜测造成不对称往返。
- “应用到表单”只替换客户端当前表单中的候选 map，不提交 revision。属性表单的“完成”仍发送原有 `UPDATE_TASK`/`UPDATE_REWARD`，服务端再次执行协议边界、编辑权限、session、预期 revision、完整候选增量校验及注册类型 Codec；Codec 失败不产生新 revision，表单和原始输入保持，配置行显示错误标记。
- 原始配置或物品选择子 Screen 关闭时会重新初始化同一个父 `QuestScreen`；所有 `EditorTextField` 在该生命周期中复用并重新注册，而不是用空控件替换，因此稳定 ID、领取策略、普通配置值、光标和选区均保持。
- 真正缺失注册的未知类型没有可用于批准修改的 Codec，因此原始 map 仍只读无损保留；复制、排序和保存既有未知数据的兼容行为不变，`BQV-117`/`BQV-118` 继续阻止发布。
- 2026-08-23 自动门禁已通过：`build -PexcludeJei --no-configuration-cache --no-daemon --console=plain` 为 157/157 JUnit；确定性 JSON 往返、非法嵌套拒绝、注册 Codec 阻断以及服务端诊断回指原始配置均有回归测试。下列焦点、滚动、模糊层级和真实扩展 Codec 交互仍由客户端人工验收决定。

## 5.10 会话级撤销与重做

- 每个服务端编辑租约维护独立的 undo/redo 栈，客户端只提交带 session、book ID 和当前 draft revision 的历史意图，不能上传任意旧草稿。恢复后的完整任务书仍通过既有分块、字节数、book ID 和 revision 校验后才替换客户端预览。
- 只有通过增量校验且产生新 revision 的 mutation 才压入 undo；无变化操作和被拒绝候选不污染历史。撤销把当前快照压入 redo，重做执行相反操作；撤销后产生新编辑会明确丢弃 redo 分支。
- 每个会话最多保留最近 64 个已验证快照。保存只更新磁盘边界和 `savedRevision`，因此可以撤销回已保存版本并正确恢复“已保存”状态；发布成功建立新 workspace 基线并清空历史。切换/关闭、断线、过期以及任意 revision 冲突同样丢弃旧时间线。
- 底栏“撤销/重做”显示服务端返回的剩余步数。任一属性、依赖、task/reward 或结构表单仍有未提交客户端输入时按钮禁用；历史同步期间沿用 mutation 忙碌状态，不能并发保存、发布、编辑或续期。

### 5.10 客户端人工检查

1. 连续执行两个容易辨认的操作，例如创建任务 A、创建任务 B；确认撤销计数依次变为 1、2，重做计数保持 0。
2. 连续撤销两次，确认 B、A 按相反顺序消失，计数变为撤销 0/重做 2；再重做两次，确认内容和稳定 ID 完整恢复，且每一步只同步一个服务端 revision。
3. 撤销一次后执行新的有效编辑，确认重做计数立即清零；无变化操作、非法字段和服务端拒绝不能增加撤销计数。
4. 保存草稿后再编辑并撤销回已保存 revision，确认底栏从“未保存”恢复为“已保存”；再次重做后恢复未保存状态。保存本身不得清空历史。
5. 打开任一尚未完成的属性或原始 JSON 表单，确认撤销/重做按钮禁用且不会丢失输入；完成或取消表单后按服务端历史状态恢复可用性。
6. 发布并应用成功后确认两项计数都归零；切换任务书、退出编辑再进入、断线重连或制造 revision 冲突后，也不得复用上一条会话/时间线的历史。
7. 在 720p/1080p 和 GUI scale 2/3 下检查新增底栏按钮、计数、禁用颜色和 Tooltip；状态文本不得与撤销按钮重叠。

## 5.11 编辑器发布闭环（提前接入）

- 点击“发布并应用”后，客户端先向服务器请求与当前 session、book ID、draft revision 绑定的发布审阅。服务器复用真实发布的完整校验和 revision guard，并同时生成相对 WORKSPACE 的语义差异；预检本身不保存、不写 workspace、不部署也不 reload。
- 审阅弹层显示发布是否允许、工作区与目标 revision、完整诊断/变更计数和“备份替换后 reload”策略。协议按稳定上限返回诊断与差异行，超限时明确显示列表已截断；只有服务器判定允许且审阅 revision 仍等于当前草稿时，确认按钮才可启动既有发布流水线。
- 诊断与语义差异行显示稳定代码，以及本地化的变化类型、对象种类和常用属性名；次行保留对象 ID 并直接摘要前后值，悬停可查看完整消息或未截断值。语义差异为空时显示“没有内容更改”，不留下难以判断的空白列表。点击仍存在的章节、任务、task 或 reward 会切换到所属章节并选中对应任务；已被删除而无法定位的对象不会伪造选择。
- 固定底栏提供“发布并应用”，确认框明确展示 `保存 → 校验 → 发布 → 备份部署 → reload`。按钮在任务属性、依赖或结构表单尚未完成时禁用，避免把仅存在于输入框的值误认为已提交草稿。
- 单次客户端请求不绕过阶段 4 边界：服务端依次按当前会话、权限、book ID 和 draft revision 执行 save、publish、带备份 replace deploy 与异步 reload；任一步失败立即停止，并在错误消息中说明之前已经完成的持久化阶段。
- Windows 短暂保留目录句柄时，workspace 发布、世界数据包部署和备份恢复的原子移动都执行相同的短暂有界重试；成功时必须在同一次“发布并应用”内继续到 reload，最终失败则保留异常类型并按原事务边界回滚，不能要求玩家再次发布来补完部署。
- ACTIVE/WORKSPACE 来源草稿允许逐字保留其来源 revision 已有的未知扩展诊断；新诊断或数量增加仍阻止发布。失败响应附带首条诊断代码、对象 ID 和正文，固定底栏从屏幕左边缘计算可用宽度，展开导航栏时也不会把错误截成单独的“编辑器”。
- ACTIVE 草稿旁已有同 ID workspace 时，若 workspace revision 仍等于该草稿的 active 来源基线，可安全发布并由原子备份流程替换；只有 workspace 已独立变化时才以 `WORKSPACE_ALREADY_EXISTS` 拦截。revision 冲突响应显示稳定冲突代码及期望/实际 revision 摘要，服务端审计消息也保留首条冲突原因。
- 发布/reload 后即使编辑会话关闭再打开，服务端也会在“磁盘草稿 revision 与 workspace revision 完全相同”时恢复或推进 WORKSPACE 来源基线；该规则覆盖首次 ACTIVE→WORKSPACE 和后续每轮 WORKSPACE→WORKSPACE 重复发布，后续编辑可正常保存。两者分叉时不会自动重基线或合并。保存和发布的 revision guard 错误都附带首条稳定冲突代码与期望/实际 revision 摘要。
- reload 成功后复用在线玩家 reconcile/sync，编辑会话回到“草稿已保存”状态；客户端在异步期间显示独立的发布中状态并阻止并发 mutation/save/close。
- 周期租约续期不会在 mutation/save/publish/close 等前台操作期间启动；操作开始前已经在途的续期响应只能刷新租约元数据，不能把客户端提前切回可编辑状态。发布的 save/workspace/deploy/renew/reload 阶段诊断及高频状态审计使用 DEBUG 日志，正常 INFO 日志不持续输出这些状态；文件形式的作者审计记录保持不变。

### 5.11 客户端人工检查

1. 对一个含未保存修改的合法草稿点击“发布并应用”，确认先显示“正在生成发布差异”，随后弹层列出 WORKSPACE→草稿 revision、变更总数和备份策略；此时取消不得保存或发布任何内容。
2. 再次打开审阅，确认标题、任务属性、位置、依赖以及 task/reward 增删改分别以语义差异出现，而不是整份 JSON 文本；悬停长值可看完整前后内容。
3. 点击一个任务、task 或 reward 的差异/诊断行，确认弹层关闭、自动切换所属章节并选中该任务；点击已删除且不再存在的对象时保持弹层，不能跳到无关任务。
4. 制造会阻止发布的新增校验错误，确认弹层显示错误代码、对象 ID 和路径，“暂不可发布”按钮禁用，且不会执行保存、workspace 写入、部署或 reload。
5. 在审阅返回后通过另一管理入口改变 workspace 或草稿 revision，再尝试确认；旧审阅不得发布新 revision，服务端 revision guard 仍应拒绝外部 workspace 分叉。
6. 在 720p/1080p 与 GUI scale 2/3 下检查弹层、滚动条、行 Tooltip 和按钮；长列表可滚动，内容不得越过上下快捷栏，Esc/取消均回到原编辑状态。
7. 连续执行多次有实际更改的“发布并应用”，每次成功提示后立即退出编辑模式确认 active 内容已变化；不得出现审阅已无更改但 active 仍是旧内容、必须第二次发布才 reload 的中间状态。

## 5.12–5.14 冲突恢复、输入可访问性与性能收尾

- 客户端收到 revision 冲突后保留上一份可信预览但锁定一切写入。“从服务器刷新”重新取得租约当前权威草稿；“另存恢复副本”由服务器复制权威内容到自动生成的新任务书 ID 后切换会话；“退出并放弃”不依赖过期 revision 即可释放本人冲突租约。任何路径都不接受客户端上传整本任务书。
