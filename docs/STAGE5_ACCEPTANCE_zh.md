# BRNQuest 阶段 5 验收记录

## 第一批：编辑入口、目录、会话与只读草稿预览

> 对应计划项：5.1 与 5.2 的基础链路。第一批不提供节点或属性修改；它先冻结目标服务器权限、任务书选择、编辑租约、草稿同步和不重排现有界面的交互边界。

### 已实现行为

- `AuthorApi.catalog` 只向目标服务器权限等级 2 的在线管理员返回可成功解码的服务器草稿；目录按完整 `namespace:path` 稳定排序，客户端本地文件不参与。
- 网络协议升级为 `2`，增加目录请求、打开/续租/关闭会话、会话结果和带 session/revision 身份的草稿分块。服务端限制目录数量、元数据大小、任务书大小、节点数量和单块大小。
- 客户端使用独立 `ClientEditorState` 接收并校验草稿；active 玩家任务书不被草稿覆盖。草稿 ID、内容 revision、字节数或分块身份不一致时不会进入编辑模式。
- 编辑会话每 30 秒自动续租。关闭界面、正常退出编辑模式、切换任务书和断线均沿用服务端租约释放语义；若玩家在打开请求尚未返回时关闭界面，迟到的租约会立即关闭。
- `QuestScreen` 保持既有左侧导航 `150px`、右侧详情 `250px`、折叠把手和画布边界。标题/ID、目录、编辑开关与会话状态均绘制为原画布范围内的悬浮层，查看/编辑切换不会改变三块主区域的像素宽高。
- 浏览相机、章节、缩放和导航折叠状态按“服务器 + 任务书 ID”隔离；切换两本任务书不会复用另一书的视口状态。
- 编辑草稿中的节点使用中性编辑配色，任务与奖励行不接受游玩提交/领取输入，避免把作者预览误当作 active 进度界面。

### 自动验证

- 默认 `runGameTestServer`：16/16 required GameTest；远程管理员用例增加“普通玩家目录拒绝、管理员读取目标服务器目录”检查。

4. 记录左栏、画布和右栏边界，进入编辑模式后再次截图；三块区域边界必须保持原坐标，仅新增画布内悬浮元素。
5. 打开标题下拉列表并切换两本草稿；确认标题、完整 ID、草稿内容和各自章节/相机位置不串书。
6. 确认左下角依次显示打开、接收草稿、草稿已保存/未保存和剩余租期；停留超过 30 秒后租期因自动续租恢复。
7. 在“正在打开服务端编辑会话”时关闭界面，再次打开同一本书；不应出现 `BOOK_ALREADY_EDITED` 的不可见占用。

若发现问题，请保留进入前后截图、GUI scale、窗口尺寸、任务书 ID、左下角稳定错误代码和服务端 `latest.log`。

## 第二批：当前任务书入口、可辨识目录与任务属性修改

- 右下角入口改为“编辑当前任务书”。当前生效任务书尚无草稿时，目标服务器在重新检查管理员权限后创建 `ACTIVE` 来源草稿；已有草稿则复用，并统一通过租约与 revision 检查打开。
- 标题下拉菜单在没有搜索词时只展示与当前画面任务书 ID 完全相同的草稿，避免历史测试、导入和备份草稿淹没常用目标。输入标题或完整/部分 ID 后才搜索其他服务器草稿。
- 目录行在不改变导航栏、画布和详情栏宽度的前提下扩展为“标题 + ID”两行；悬停提供不截断的标题、完整 ID 和来源说明。
- 编辑模式中选中任务节点后，右侧详情固定显示“编辑任务属性”。首个可写表单覆盖标题、副标题和描述；任务 ID、章节、坐标、依赖、任务条件、奖励和未知扩展内容保持原值。
- 客户端只发送字段级意图。服务器重新读取会话快照、按稳定任务 ID 构造候选、运行 `DraftBookEditor` 与增量验证，再返回新 revision 的完整草稿分块；客户端验证完成前继续显示上一个可信草稿。
- 属性表单在打开时不再渲染其下方的 task/reward 物品图标；任务书下拉层使用高于普通物品的 GUI 深度、低于最终 tooltip 的深度。文本框为失焦文字显式指定可读颜色。
- 增量提交只阻止本次修改新增或增加数量的 `ERROR/FATAL` 诊断。草稿原本已有的未知扩展诊断不会阻止标题等无关字段修改，未知配置仍逐字保留；真正新增的非法空标题等问题仍会被拒绝。
- 任务属性表单的“完成”只提交到服务器内存编辑会话；底部明确显示“保存草稿”，成功后状态变为“草稿已保存”。保存相对磁盘基线比较诊断，因此已有未知扩展不会阻止持久化，新错误仍会被拒绝。
- 草稿未保存时，退出编辑、切换任务书或按 Esc 都先显示丢弃确认。若界面被其他界面强制替换，客户端保留仍有效的会话投影，重新打开任务书可在租期内继续编辑；断线仍由服务器释放会话。
- 顶部任务书标题/选择栏与底部状态/保存/退出栏占用固定的全屏宽度。导航、画布和详情面板统一限制在两条快捷栏之间；反复展开左右面板不会改变快捷栏控件的位置或宽度。

## 5.3–5.4 章节结构与任务节点编辑

1. 在编辑模式左栏使用“+ 组”创建章节组，再使用“+ 章节”或章节组右键菜单创建章节；完整 ID 必须使用 `namespace:path`，显示名称可随后通过右键“改名”修改。
2. 对章节组和章节分别执行“向上移动/向下移动”，确认顺序在服务端草稿同步完成后稳定，并在保存、退出、重新进入后保持。
3. 删除非空章节或章节组，确认界面先显示受影响章节数、任务数和依赖清理范围；取消不应改变 revision，确认后不得留下悬空任务或依赖。
4. 在章节空白画布右键创建任务节点；节点右键可以复制或删除。复制必须产生新的 quest/task/reward 稳定 ID，不能与原节点共享子对象 ID。
5. 左键拖动单个节点；按住 Ctrl 选择多个节点后拖动任一已选节点。拖动期间只本地预览，松开后一次提交全部最终坐标；缩放、平移和左右栏切换不改变已保存图坐标。
6. 保存草稿并退出编辑，再重新进入，确认章节结构、节点数量、顺序和坐标全部恢复。客户端视觉验收同时覆盖 720p/1080p、GUI scale 2/3、菜单边缘自动收拢和危险确认层级。

## 后续编辑功能的 UI 组件基础

- `client/ui/component` 统一提供 `UiRect`、`QuestScreenLayout`、编辑按钮、编辑文本框、滚动条、弹出菜单、确认对话框和单一活动弹层宿主。后续依赖、task、reward 和发布界面应复用这些组件，不再在 `QuestScreen` 中复制颜色、矩形和命中算法。
- `QuestScreen` 仍是页面编排与语义操作边界：组件只负责布局、绘制、焦点或命中结果，不持有编辑租约、revision，也不直接发送网络 mutation。
- 画布节点和依赖连线继续使用即时渲染、视口裁剪及图坐标命中；不会为每个节点创建原生 Widget，以免节点数量增加后引入不必要的对象和变换复杂度。
- 任一时刻最多存在一个捕获输入的编辑弹层。目录、右键菜单、结构表单、删除确认和丢弃确认共享 Esc、滚轮、拖动及外部点击屏蔽规则，防止输入穿透到底层画布。
- 自动测试固定上下快捷栏、左右面板对中央画布的影响、内容区边界、弹出菜单边缘收拢、确认框按钮位置及弹层互斥。完整 JUnit 当前为 120/120。
